# Fortune maintenance checklist

Use the Admin navigation for routine updates. Save drafts first, preview them,
then publish only after checking the public page on phone and desktop.

- **Media:** upload one original image, add human alt text, and confirm it is
  visible before attaching it to an Event or News item. Private learner files
  belong in the private document workflow, never the public Media bucket.
- **Team:** edit the existing person or group rather than creating duplicates;
  confirm role, affiliation, order, portrait, and alt text.
- **Programmes / Academy:** keep one canonical enrolment route per programme;
  test the Apply/Enroll button after changing dates or availability.
- **News and Events:** use Events for upcoming sessions and News for reports or
  announcements. Mark old imports Draft until dates, links, images, and copy
  are reviewed. Past events must not retain an active registration CTA.
- **Resources:** use Publications for verified DOI links and Recorded webinars
  for confirmed recordings. A YouTube link is an external URL, not a file
  upload. Check every download in a signed-out browser.
- **Testimonials:** publish only a traceable quote with name, role, image
  permission, and source. Text-only testimonials are acceptable; placeholders
  are not.
- **Impact:** leave evidence-thin stories as Coming soon until source material
  and approval are recorded. Do not publish invented outcomes or numbers.
- **After publishing:** open the page signed out, check keyboard focus and
  mobile layout, and confirm the sitemap/redirect behavior if a slug changed.

Never commit `.env`, `cgi-bin.zip`, `localhost.sql`, certificates, passports,
or other personal records. Keep the source archive as the recovery backup.
